# 편집자 파이프라인 운영 (#128)

편집자를 claude.ai 예약 루틴에서 백엔드 파이프라인(ADR 0006, 설계 `docs/design/editor-pipeline.md`)으로 옮기는 운영 절차다. 운영 `.env`·재배포·루틴 켜고 끄기는 조율자(대장)가 한다. 작업자는 운영 서버·운영 `.env`·운영 DB에 쓰지 않는다.

## 모드

| `EDITOR_PIPELINE_MODE` | 하는 일 |
|---|---|
| `off`(기본) | 아무것도 하지 않는다. 진행 중이던 실행도 나아가지 않는다. |
| `shadow` | 매 슬롯 1~3단계를 부르고 결과는 `EditorCall`에만 남긴다. 수집물·기사·분석·포스트를 바꾸지 않는다. 루틴이 계속 게시한다. |
| `live` | 단계 결과를 서비스 함수로 저장한다(주체 편집자). 버림, 기사 생성·갱신, 분석, 카카오 포스트 초안까지 한다. **루틴을 끈 뒤에만 켠다.** |
| 그 밖의 값(오타 등) | `off`와 같다. 로그에 경고가 남는다. |

저장할지는 실행을 열 때의 모드로 정해진다. 그림자로 연 실행은 도중에 `live`로 바꿔도 끝까지 아무것도 저장하지 않는다.

## 키 넣기

1. 대표의 Anthropic API 키는 admin 「운영 설정」(`<DJANGO_ADMIN_PATH>/core/runtimesetting/`, #164)에서 넣는다. 저장 즉시 web·scheduler에 반영되고(재시작 없음) DB에는 `RUNTIME_SETTINGS_KEY`(운영 `.env`의 Fernet 키)로 암호화돼 남는다. 화면은 「설정됨 · 끝 4자리」만 보이고 「연결 시험」(`GET /v1/models`)이 있다. admin에 값이 없으면 운영 `.env`의 `SANDCORP_NEWS_CLAUDE_KEY=…`를 쓴다. SDK 기본 이름 `ANTHROPIC_API_KEY`는 읽지 않는다.
2. 키가 비어 있으면 `run_editor`는 로그만 남기고 건너뛴다. 모드가 `shadow`·`live`여도 같다.
3. 키 값은 이슈·PR·로그·대화에 남기지 않는다. 손으로 확인할 때는 `~/.config/sandcorp/news-claude.env`(권한 600)를 `set -a; source …; set +a`로 환경 변수에만 올린다.

## 지출 한도

- Anthropic Console 지출 한도는 **월 $20**이다. 앱 상한 `EDITOR_MONTHLY_BUDGET_USD`는 **$18**로 그보다 낮다.
- 앱 상한에 닿으면 남은 기간의 실행을 건너뛰고(`EditorRun.status=skipped_budget`) Discord 「편집 예산 초과」를 보낸다. 다음 달(KST) 1일에 풀린다.
- Console이 한도로 거절하면(지출 한도로 보이는 HTTP 4xx) 같은 건너뜀으로 처리한다.
- 한도를 올릴 때는 Console 한도를 먼저 올리고, 그다음 `EDITOR_MONTHLY_BUDGET_USD`를 Console 한도보다 낮게 올린다.
- 이번 달 합계는 admin 「편집자 실행」 목록 위에 보인다.

## 그림자 → 게시 전환 순서

1. 그림자 기간(3~7일)에 admin 「편집자 실행」 → 상세 「그림자 비교」로 판단 일치율, 사실 오류, 비용을 본다. 대표가 확인한다.
2. **먼저 claude.ai 예약 루틴(06:40·12:40·18:40)을 끈다.** 순서를 바꾸면 루틴과 파이프라인이 같은 수집물을 두고 경쟁한다. 저장은 견디지만(이미 묶인 수집물은 빼고 저장) 같은 뉴스가 두 기사로 생길 수 있다.
3. 같은 날 admin 「운영 설정」에서 `EDITOR_PIPELINE_MODE`를 `live`로 저장한다(재배포 없음; 운영 `.env`를 바꾸고 재배포해도 된다). 다음 매시 25분 주기부터 적용된다. 이미 열린 그림자 실행은 그림자로 끝난다.
4. 첫 게시 슬롯(06:25·12:25·18:25 KST) 뒤에 확인한다.
   - admin 「편집자 실행」: 모드 「게시」, 메모의 「저장: 새 기사 N · 갱신 M · 버림 K」, 비용.
   - 「편집 호출」 상태: `saved`가 정상이다. `skipped`는 까닭이 `error`에 있다(수집물이 이미 묶임·버림, 숨긴 분석, 올린 포스트). `failed`는 「저장 실패: …」(분야 삭제·기사 삭제) 또는 모델 호출 실패다.
   - 사이트에 기사·분석이 붙었는지, admin 「포스트」에 카카오 초안이 생겼는지 본다.
   - 배치(기본)이면 기사는 슬롯 뒤 10분~1시간, 분석은 그 뒤 한 주기 안에 붙는다.
5. Discord를 본다. 「편집자 미실행」이 조용해야 한다. 이 경보는 게시 실행을 센다(그림자는 세지 않는다).

## 되돌리기

1. 운영 `.env`를 `EDITOR_PIPELINE_MODE=off`로 바꾸고 재배포한다.
2. claude.ai 예약 루틴을 다시 켠다.
3. 파이프라인이 만든 기사·분석·포스트 초안은 보통 기사라 그대로 둔다. 고칠 것은 admin에서 고친다.
4. 예약 중이던 수집물(끝나지 않은 작성 호출이 잡은 것)은 미처리로 남는다. `off`이면 실행이 더 나아가지 않으므로 실행 시작 48시간 뒤 예약이 풀리고, 그때부터 24시간 자동 버림 대상이 된다. 그 전에 루틴이 처리할 수 있다.
5. 배치 장애만 의심되면 끄지 말고 `EDITOR_USE_BATCH=false`(동기)로 먼저 바꿔 본다.

## 예약

게시 실행의 분류가 새 기사·갱신으로 정한 수집물은 작성 호출이 끝날 때까지 미처리로 남는다. 그동안 다음 실행의 분류 입력에서 빠지고, `prune_items`의 24시간 자동 버림에서도 빠진다. 호출이 저장·실패·만료·건너뜀으로 끝나면 풀린다. 계산은 `services/editor_reserve.py`가 한다.
