# 대표 인증은 독립 인증 서비스가 맡는다

sandcorp.co.kr(portfolio)과 이 사이트는 모두 대표 한 명의 로그인(비밀번호 + TOTP)과 원격 MCP용 OAuth 2.1 인가가 필요하다. portfolio #8이 아직 구현 전이므로, 인가 서버를 portfolio 안에 두지 않고 세 번째 저장소의 독립 서비스(sandcorp-auth, auth.sandcorp.co.kr)로 만들어 두 사이트가 리소스 서버로서 토큰만 검증하기로 했다. 인증 대상은 대표 1인뿐이며 방문자 계정은 없다. 액세스 토큰은 서명된 JWT이고 리소스 서버는 JWKS로 오프라인 검증한다.

편집자(Claude Code 클라우드 예약)는 claude.ai 커넥터로만 MCP에 붙을 수 있고, 커넥터는 대표가 한 번 OAuth 로그인하면 claude.ai가 리프레시 토큰을 보관·갱신한다. 따라서 편집자는 별도 기계 계정이 아니라 「편집자」 스코프만 가진 커넥터로 동작하는 대표의 세션이다. client credentials는 만들지 않는다.

## Considered Options

- **portfolio를 인가 서버로, 이 사이트는 리소스 서버로**: 새 배포물이 없지만 포트폴리오 사이트가 다른 사이트의 로그인을 떠안아 책임이 섞인다.
- **사이트마다 자체 OAuth 서버**: 인증 코드와 로그인이 두 벌.
- **독립 서비스 (채택)**: 배포물이 하나 늘지만 인증 코드·대표 계정·클라이언트 등록이 한 곳에 모인다.
- **불투명 토큰 + introspection**: 즉시 폐기가 쉽지만 리소스 서버가 요청마다 인증 서비스에 의존한다. JWT + JWKS를 택하고 즉시 폐기는 리프레시 차단과 짧은 액세스 토큰 수명으로 대신한다.

## Consequences

- portfolio #7(관리자 로그인)은 sandcorp-auth로 옮겨 가고, #8은 "인가 서버 구현"에서 "sandcorp-auth 토큰 검증 + 원격 MCP 뼈대"로 범위가 바뀐다.
- 인증 서비스가 내려가면 새 로그인과 토큰 갱신이 멈춘다. 이미 발급된 액세스 토큰은 만료 전까지 유효하고, 공개 페이지는 영향 없다.
- 편집자 MCP는 뉴스 서버가 배포된 뒤 대표가 claude.ai에 커넥터로 등록·로그인해야 동작한다.
