# 대표 인증은 독립 인증 서비스가 맡는다

sandcorp.co.kr(portfolio)과 이 사이트는 모두 대표 한 명의 로그인(비밀번호 + TOTP)과 원격 MCP용 OAuth 2.1 인가가 필요하다. portfolio #8이 아직 구현 전이므로, 인가 서버를 portfolio 안에 두지 않고 세 번째 저장소의 독립 서비스(auth.sandcorp.co.kr)로 만들어 두 사이트가 리소스 서버로서 그 토큰만 검증하기로 했다. 인증 대상은 대표 1인과 기계 클라이언트뿐이며 방문자 계정은 없다. 편집자 같은 비대화형 자동화는 client credentials로 짧은 토큰을 받는다.

## Considered Options

- **portfolio를 인가 서버로, 이 사이트는 리소스 서버로**: 새 배포물이 없지만 포트폴리오 사이트가 다른 사이트의 로그인을 떠안아 책임이 섞인다.
- **사이트마다 자체 OAuth 서버**: 인증 코드와 로그인이 두 벌.
- **독립 서비스 (채택)**: 배포물이 하나 늘지만 인증 코드·대표 계정·클라이언트 등록이 한 곳에 모인다.

## Consequences

- portfolio #8은 "인가 서버 구현"에서 "외부 인증 서비스 토큰 검증"으로 범위가 바뀐다.
- 인증 서비스가 내려가면 두 사이트 모두 관리 기능(admin, MCP)을 쓸 수 없다. 공개 페이지는 영향 없다.
