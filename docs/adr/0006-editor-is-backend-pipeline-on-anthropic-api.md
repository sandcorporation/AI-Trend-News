# 편집은 백엔드가 Anthropic API로 부르는 고정 단계 파이프라인이 한다

ADR 0002는 claude.ai 예약 자동화(편집자)가 원격 MCP로 들어와 도구를 부르며 편집하는 방식을 택했다. 이 결정을 거두고, 백엔드가 스케줄러 주기 안에서 Anthropic Messages API를 직접 불러 **정해진 세 단계(분류 → 기사 작성 → 분석·포스트 초안)** 를 돌린다. 각 단계는 구조화 출력(`output_config.format`)으로 JSON을 받고, 저장은 MCP 도구가 부르던 것과 같은 서비스 함수(`services/articles.py` 등)가 한다. 비용은 Anthropic Console API 크레딧(월 약 US$100)으로 낸다.

에이전트 루프를 API로 그대로 옮기지 않은 것은 비용 때문이다. 2026-10-30 06:40 실행(run 26)은 88턴에 도구 결과 약 30만 자였고, 루프는 턴마다 쌓인 문맥을 다시 보내므로 Sonnet 5.5로도 회당 약 $1.5~2(월 $150~200)가 든다. 단계를 고정하면 각 호출이 필요한 입력만 받아 문맥이 쌓이지 않고, 지연이 상관없는 2·3단계는 Message Batches(50% 할인)로 보낼 수 있어 같은 규모가 월 $50 안팎으로 추정된다(`docs/design/editor-pipeline.md` 비용 추정).

## 결과

- 서버에 LLM 호출 코드가 생긴다. 호출은 어댑터 한 파일(`adapters/anthropic.py`)에만 두고, 시험은 가짜 클라이언트로 돌린다. 시험은 실제 API를 부르지 않는다.
- 편집 기준의 원천은 그대로 `automation/editor.md`다. 단계별 프롬프트는 이 파일의 절을 골라 조립하고, 단계마다 다른 「입력·출력 설명」만 `automation/stages/`에 둔다. 기준을 바꾸려면 여전히 이 파일을 고치지만, 이제는 배포해야 반영된다.
- 편집자의 재량이 줄어든다. 루프 편집자는 원문을 더 읽을지, 어느 기사를 다시 볼지 스스로 골랐다. 파이프라인은 단계마다 정한 입력만 본다. 원문 길이·처리 건수 상한은 설정과 코드가 정한다.
- 실행마다 단계별 토큰·캐시 토큰·추정 비용을 DB에 남기고, 월 예산 상한을 넘으면 실행을 건너뛰고 경보를 보낸다.
- 처음에는 그림자 모드로 돈다. 결과를 별도 기록에만 남기고 수집물·기사는 건드리지 않으며, 기존 claude.ai 루틴이 계속 게시한다. 대표가 비교해 확인하면 루틴을 끄고 게시 모드로 바꾼다.
- MCP 편집자 도구는 남긴다. 대표가 손으로 편집하거나 Claude로 수동 편집할 때 쓴다.
- 새 큐(Celery 등)는 들이지 않는다. 기존 `run_scheduler` 매시 주기가 편집 시각에만 실행을 시작하고, 배치가 끝났는지는 그 뒤 주기마다 확인한다.
